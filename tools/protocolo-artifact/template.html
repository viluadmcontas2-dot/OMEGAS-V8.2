Packet Structure (decoded from serial capture)

CONFIRMED from Portmon capture + Ghidra decompilation (175 functions, 275KB pseudocode). TX checksum: 134/134 verified. RX checksum: 7/7 verified after correcting the scope. Protocol confirmed at source code level. 
PHYSICAL LAYER:
  Baud: 9600 (operational), 38400 (discovery probe only)
  Format: 8N1 (8 data bits, no parity, 1 stop bit)
  Flow control: None (RTS cleared, DTR cleared)
  Timeouts: ReadInterval=100ms, ReadMultiplier=50ms, ReadConstant=200ms
  Buffer: 4096 bytes in/out
  MCU clock: 8 MHz (boot baud = 8000000 / (divisor × 16))

PORT DISCOVERY SEQUENCE:
  1. For each serial port (COM, Silabser, etc.):
     a. Open at 38400 baud, 8N1
     b. Send single byte: [0x00]
     c. Wait 250ms for response
     d. If [0x80] received → ECU found on this port
     e. If TIMEOUT → close, try next port
  2. Reopen found port at 9600 baud for communication

CONNECTION HANDSHAKE (from Ghidra: TAebProtocol.Connect):
  1. TX: [01] [00] [3A] [3B]      → Set parameter 0 = 0x3A
  2. Wait for ACK
  3. TX: [00] [25] [25]            → Get protocol version (sub-cmd 0x25)
  4. RX: echo + ACK + version data
  5. First byte of response = protocolVersion (stored at +0x2C4)

DISCONNECT (from Ghidra: TAebProtocol.Disconnect):
  TX: [00] [01] [01]              → System sub-cmd 0x01 = disconnect

TX PACKET (Host → ECU):
  ┌──────┬────────────────┬──────────┐
  │ CMD  │   PARAMETERS   │ CHECKSUM │
  │ 1 B  │   0..N bytes   │   1 B    │
  └──────┴────────────────┴──────────┘
  Checksum = SUM(CMD + all PARAM bytes) mod 256
  ✓ Verified: 134/134 packets (100%)

RX PACKET (ECU → Host):
  ┌───────────────┬──────┬──────┬───────────┬──────────┐
  │  ECHO OF TX   │ ACK  │ LEN  │   DATA    │ CHECKSUM │
  │  (full copy)  │ 1 B  │ 1 B  │ LEN bytes │   1 B    │
  └───────────────┴──────┴──────┴───────────┴──────────┘

  ACK BYTE (from Ghidra: TAebProtocol.IsAck):
    0x53 ('S') = Success, data follows
    0xCA       = NACK with error code (reads 2 extra status bytes)
    0x96       = Timeout/retry condition (reads 1 byte + checksum)
    Other      = Communication error, triggers reconnect

  Checksum = SUM(ACK + LEN + DATA bytes) mod 256
  (Echo bytes are NOT included in RX checksum)
  ✓ Verified: 7/7 known packets match H2 hypothesis

Protocol Versioning (from Ghidra)

  Version negotiated at connect via: [00] [0x25] [CK]
  First response byte → protocolVersion (stored at self+0x2C4)

  Version 0-1: 1-byte addressing (address < 0xFF)
    GetNumber  = CMD 0x08, [08] [addr_lo] [CK]
    GetVector  = CMD 0x28, [28] [addr_lo] [CK]

  Version 1 (extended): 2-byte addressing for addr ≥ 0xFE
    [08] [0xFF] [addr+1] [CK]  (marker 0xFF + offset)

  Version 2+: 2-byte addressing natively
    GetNumber  = CMD 0x09, [09] [addr_lo] [addr_hi] [CK]
    GetVector  = CMD 0x29, [29] [addr_lo] [addr_hi] [CK]

  Baud rate range: 1200 (0x4B0) to 115200 (0x1C200)
  Boot baud: calculated as 8000000 / (baudTable[index] × 16)

AEB_DATA Structure (from Ghidra)

  struct AEB_DATA {       // 16 bytes, passed to all Get/Set functions
    uint32  SerialCode;   // +0x00  Parameter address/ID (0x00..0x1FF)
    uint32  ElementCount; // +0x04  Number of elements (vectors/matrices)
    uint32  ElementSize;  // +0x08  Bytes per element: 1, 2, or 4
    uint32  IsSigned;     // +0x0C  0=unsigned, nonzero=signed
  };

  Address range by protocol version:
    v0: SerialCode 0x00..0xFE (1-byte addressing)
    v1: SerialCode 0x00..0x1FE (extended: 0xFF marker + offset)
    v2: SerialCode 0x00..unlimited (native 2-byte addressing)

IDENTIFICATION_DATA Structure

  struct IDENTIFICATION_DATA {  // 4 or 6 bytes from GetIdentification [00][02]
    uint8  device_code_lo;     // [0] Hardware code low byte
    uint8  device_type;        // [1] 0x03 = bootloader mode
    uint8  hardware_family;    // [2] Family ID (0..0x0B+)
    uint8  hardware_version;   // [3] bit7 = dual-flash flag
    uint8  extended_lo;        // [4] (only if count==6)
    uint8  extended_hi;        // [5] (only if count==6)
  };

TAebPacketData Object Layout (from Ghidra)

  Real-time polling: GetPacket(channel_id) with configurable interval
  Min interval: 20ms. Max response: 251 bytes. Default: 1000ms.

  Key offsets:
    +0x44  ElementCount (default 1)
    +0x58  ElementSize (1, 2, or 4)
    +0x60  last_reload_success (bool)
    +0x68  IsSigned flag
    +0x6C  SerialCode → channel ID for GetPacket
    +0xC4  last ComFail error code
    +0x148 current_value (raw integer)
    +0x150 data_offset in response buffer
    +0x158 TimeInterval (ms)

  UpdateData extracts value at: response_ptr + data_offset + 4
  Each TAebPacketData is configured for one field in the bulk response.

CheckEEpromWrite

  Polls ECU waiting for EEPROM write completion:
    Loop: GetNumber(address) until result == 0xAC
    Sleep(500ms) between polls
    Timeout after configurable milliseconds
    0xAC = "EEPROM write complete" magic value

Error Flags (ComFail bitmask at +0x44)

  Bit 0 (0x01): General error
  Bit 2 (0x04): SerialCode out of range (v0: addr > 0xFE)
  Bit 3 (0x08): Echo mismatch (SendByte verify failed)
  Bit 5 (0x20): SerialCode out of range (v1: addr > 0x1FE)
  Bit 6 (0x40): Reconnection failed
  0x8020:       GetPacket/GetVector size mismatch

  Abort mask 0x29 (bits 0,3,5): checked in SendByte/SendInt
  Abort mask 0x44 (bits 2,6):   checked in HandleFail (no retry)

9. Firmware Flash Protocol (from Ghidra)

Fully decoded from Ghidra decompilation — no live capture needed. The complete flash sequence, bootloader handshake, baud rate negotiation, and both S-record and Intel HEX formats are documented below.

Flash Sequence (ScaricaFile orchestrator)

  ┌─────────────────────────────────────────────────────┐
  │  ScaricaFile / ScaricaFileHEX / ScaricaFileS19      │
  │  Full firmware upload orchestrator                   │
  └───────┬─────────────────────────────────────────────┘
          │
  1. SaveBaud()          → Save current communication baud rate
  2. PreparaProg()       → Prepare ECU for programming
  3. Cancflash()         → Clear existing flash (erase)
  4. Progflash()         → [0x93][CK] → expect 0xA7 (flash mode)
          │                  Retry ×4 on failure
  5. Sleep(3300ms)       → Wait for bootloader to initialize
  6. ReadBootBaud()      → Read boot baud rate from ECU
  7. SetBaud(bootBaud)   → Switch host to boot baud rate
          │                  Boot baud = 8MHz / (divisor × 16)
          │
  8. ┌── LOOP: for each line in firmware file ──┐
     │  SendHEXflash() or SendS19flash()        │
     │  → Parse line, send address+data         │
     │  → Wait for 0xA7 or 'S' ACK per line     │
     │  → Progress callback on each line         │
     └──────────────────────────────────────────┘
          │
  9. Endflash()          → [0x85][CK] → expect 'S' (0x53)
 10. RestoreBaud()       → Restore original communication baud
 11. Disconnect()        → Clean disconnect from ECU

  SendToBoot(baudIndex):
    1. SaveBaud()              → Store current baud in ECU EEPROM
    2. PreparaProg()           → [prepare commands]
    3. Cancflash()             → [erase flash]
    4. Sleep(3300 ms)          → Wait for MCU to restart in boot mode
    5. ReadBootBaud()          → Read baudTable[index] from ECU
    6. bootBaud = 8000000 / (baudTable[index] × 16)
    7. SetBaud(bootBaud)       → Switch serial port to boot baud
    → ECU is now in boot mode, ready for SendHEXflash/SendS19flash

Key Design Decisions

1. Protocol Layer: Coroutine-based reactive communication

The original Delphi code uses a TimerIO polling loop. On Android, we replace this with Kotlin Flow-based reactive streams:

// Core protocol interface
interface AebProtocol {
    val connectionState: StateFlow<ConnectionState>
    val ecuData: SharedFlow<EcuDataUpdate>

    suspend fun connect(transport: Transport): Result<EcuIdentity>
    suspend fun disconnect()
    suspend fun sendCommand(cmd: Int, payload: ByteArray = byteArrayOf()): Result<ByteArray>
    suspend fun readNumber(address: Int): Result<Double>
    suspend fun writeNumber(address: Int, value: Double): Result<Unit>
    suspend fun readVector(address: Int, size: Int): Result<DoubleArray>
    suspend fun readMatrix(rows: Int, cols: Int, address: Int): Result<Array<DoubleArray>>
    suspend fun startRealtimeStream(interval: Duration): Flow<EcuPacket>
    suspend fun flashFirmware(data: ByteArray, onProgress: (Float) -> Unit): Result<Unit>
}
2. Transport Abstraction: USB-OTG replaces COM/FTDI 
// Unified transport interface
interface Transport {

4. Real-time Scope: Canvas-based high-performance rendering

The oscilloscope needs 60fps rendering of multiple data channels. Using Compose Canvas with a ring buffer:

@Composable
fun RealtimeScope(
    channels: List<ScopeChannel>,
    timeWindow: Duration = 10.seconds,
    modifier: Modifier = Modifier
) {
    Canvas(modifier = modifier.fillMaxSize()) {
        channels.forEach { channel ->
            val path = Path()
            channel.samples.forEachIndexed { i, sample ->
                val x = i.toFloat() / channel.samples.size * size.width
                val y = size.height - (sample - channel.min) /
                    (channel.max - channel.min) * size.height
                if (i == 0) path.moveTo(x, y) else path.lineTo(x, y)
            }
            drawPath(path, channel.color, style = Stroke(2.dp.toPx()))
        }
    }
}
